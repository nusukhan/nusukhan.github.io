PROJECT 01 Retrieval-augmented generation

RAG Knowledge Extraction System

ALL 12 DELIVERABLES ACCEPTED

Parallax Labs · AI/ML Engineer Internship · Python, ChromaDB, FastAPI, spaCy, scikit-learn

A language model asked a factual question answers from memory — confidently, and sometimes wrongly. This system answers only from a corpus of 5,000 Wikipedia science articles, and reports how much of each answer its sources actually support.

Over twelve weeks I built the whole pipeline, one stage per week, with each stage reviewed before the next began.

INGEST

5,000 articles collected, cleaned, chunked

Wikipedia API · HTML and special-character stripping · spaCy tokenisation and lemmatisation · unit-tested cleaning functions · 700-character chunks

INDEX

Every chunk embedded and stored with metadata

all-MiniLM-L6-v2 embeddings (384 dimensions) · ChromaDB vector store · LDA topic label and spaCy named entities attached to each chunk

RETRIEVE

Top 5 passages found by meaning, not keywords

Semantic search over embeddings · optional topic filtering · optional ranking boost for named entities · completes in about 2 milliseconds

GENERATE

An LLM answers using only those passages

System prompt forbids outside knowledge and requires a refusal when the corpus lacks the answer · rate limits, timeouts and malformed responses handled explicitly

VERIFY

The answer is checked back against its own sources

A support score reports how much of the answer appears in the retrieved text · refusals recognised as correct behaviour · source excerpts returned with every response

SERVE

Exposed as a tested REST API

FastAPI endpoints for query, corpus metadata and health · every request logged with latency · 400, 422 and 500 responses · pytest suite and concurrency test

PROJECT 02 Imbalanced classification

Real-Time Credit Card Fraud Detection

LIVE Pakistan · Machine Learning Internship · 284,807 transactions, 0.17% fraud

A model that labels every transaction as genuine scores 99.83% accuracy and catches zero fraud. That number is the anchor of this project: accuracy was rejected outright, and ROC-AUC with it.

Across five imbalance strategies, ROC-AUC varied by 0.002 while PR-AUC varied by 0.15 — ROC-AUC simply could not tell the strategies apart. I compared class weighting, SMOTE, ADASYN, SMOTEENN and random undersampling under stratified five-fold cross-validation, with resampling fitted on training folds only so no synthetic row could leak into validation.

Class weighting won — the simplest option, with no synthetic data and no discarded rows. Of three supervised models plus an unsupervised Isolation Forest, XGBoost took the highest PR-AUC. SHAP and permutation importance were then cross-checked against each other and agreed on the top features, and a chronological split tested for drift.

What it taught me: how to report a null result. Cost-sensitive threshold tuning produced exactly zero saving over the default. Rather than adjust the cost assumptions until a saving appeared, I traced why — false alarms were 0.3% of total cost, and the missed frauds were missed with very low predicted probability, so no threshold could recover them. The binding constraint was model capacity, not threshold choice. I reported that instead of manufacturing a win.

PROJECT 03 Regression, trained and deployed

Laptop Price Prediction

LIVE APP

Neural network regression · 1,275 laptops · deployed on Streamlit

An artificial neural network that estimates a laptop's price from its specifications — trained, saved with its full preprocessing pipeline, and deployed so anyone can use it in a browser.

Most of the work was feature engineering. A single screen-resolution field held four separate facts; the memory field held two drives with mixed units in one string. Both had to be parsed into usable columns. Screen width and height turned out to be 0.99 correlated — the same information twice — so I combined them with screen size into a single pixels-per-inch feature. Model names had roughly two samples each across 618 categories, so that column was dropped rather than memorised.

The trained model, the label encoders and the scaler are all saved to disk, so the app loads them and predicts in about 200 milliseconds instead of retraining for every visitor.

The network beats the linear baseline, but only modestly — which is itself a finding. Laptop pricing is largely driven by linear relationships, and the network's advantage comes at noticeably higher computational cost.

Neural network (17 → 64 → 32 → 1)0.79€231

What it taught me: theory does not always survive contact with the data. The price distribution was right-skewed, so I applied the textbook log transform — and measured that it made things clearly worse, dropping R² from 0.80 to 0.24. Small errors in log space explode after the inverse transform; one prediction came out at €174,846 against a real maximum of €6,099. I removed the transform based on the experiment rather than the rule.

PROJECT 04 Object detection

Palm Tree Counter

Aerial imagery · YOLO transfer learning · images and video

A detection model that counts palm trees in drone footage automatically — drawing a box around every tree and overlaying a live count on each frame.

I fine-tuned a YOLO detection model on a labelled aerial dataset using transfer learning, then built an OpenCV pipeline that reads video frame by frame, runs detection, draws the boxes and writes an annotated output video. On a single test image it found 94 trees with confidence above 0.90; across 817 video frames it counted between 22 and 38 trees per frame.

What it taught me: a model is only as general as its training data. It performs near-perfectly on clean top-down imagery but misses trees in dense, ground-level views — a textbook out-of-distribution failure, because that view was never in the training set. Naming the cause matters more than the headline number, and fine-tuning on labelled data from that view is the fix.

PROJECT 05 Computer vision

Handwritten Digit Recognition

Multi-class classification · full OpenCV detection pipeline

A system that finds handwritten digits inside an image and labels them — built from raw pixels to prediction rather than wrapping a pre-trained model.

I trained a support vector machine on 1,797 handwritten digit images and evaluated it on a held-out test set for an honest accuracy figure, alongside a confusion matrix and per-digit precision and recall. The detection side is a complete OpenCV pipeline: grayscale, blur, threshold, contour detection, crop each candidate, predict, and draw a labelled bounding box.

PROJECT 06 Deep learning for images

Fruit Image Classification with a CNN

Convolutional neural network · Fruits-360 dataset · 4 classes, 2,881 images

A convolutional network that names the fruit in a photograph and reports how confident it is — built to understand what a CNN actually does differently from a plain neural network.

A CNN reads an image in small patches, learning edges, colours and shapes before it learns what they add up to — which is why it outperforms a flat network on images. I built a Sequential model (rescaling, convolution, pooling, flatten, dense) and trained it on 2,160 images across apple, banana, orange and strawberry, then evaluated it on 721 held-out images with a per-class precision and recall report.

What it taught me: read the score before celebrating it. 100% accuracy is not a sign of a great model here — it is a sign of an easy dataset. Fruits-360 images sit on a plain background at a consistent angle, so the classes are almost trivially separable. On messy real-world photos this model would do considerably worse. The honest next steps are data augmentation and more varied images, not a bigger network.

PROJECT 07 Medical imaging

Pneumonia Detection from Chest X-Rays

Convolutional neural network · FastAPI web app · Chest X-Ray Pneumonia dataset (Kaggle)

A CNN that reads a chest X-ray and classifies it as Normal or Pneumonia with a confidence score, served through a web interface. Built for educational purposes — not a medical diagnostic tool.

I built a Sequential CNN from scratch (three convolution-and-pooling blocks, dropout, ~4.8M parameters) and trained it on 5,216 chest X-rays. The dataset is imbalanced — pneumonia cases outnumber normal ones roughly three to one — so a model that guessed "pneumonia" every time would still score ~74% accuracy. Rather than delete data, I used class weights to make the model pay more attention to the under-represented Normal class, and rebuilt the validation set by splitting 20% off the training data because the dataset's own validation folder held only 16 images. I deliberately left out horizontal flips: the heart sits on the left of the chest, so a mirrored X-ray is anatomically impossible and would teach the model wrong patterns.

0.96

0.82

What it taught me: in medical AI, recall matters more than accuracy. The 91% headline hides the real story the confusion matrix tells. Pneumonia recall of 0.96 means the model catches 96 of every 100 sick patients — and the most dangerous mistake here is a false negative, a sick patient told they are healthy. The model is weaker at identifying Normal cases (0.82 recall), exactly the kind of weakness accuracy alone would hide and precision and recall expose.
